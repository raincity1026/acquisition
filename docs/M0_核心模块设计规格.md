## 1. M0 目标与范围

打通一条最小数据链，证明骨架可用：

```
Baostock → 标准化(复权/停牌/symbol) → 入库(PostgreSQL) → 查询/聚合 → GET /api/kline
```

**M0 做**：DataProvider 抽象 + BaostockProvider、数据模型与入库、按需加载、单股 K 线 API（日/周/月、复权切换）。
**M0 不做**：前端（M1）、对比 API 接前端（M2 用，但本文先定契约）、账号（M3）、盘后定时任务（M4，本文标好挂载点）。

## 3. 数据模型（PostgreSQL）

### 3.1 `instruments`（标的元数据，支撑搜索 + 增量）
| 字段 | 类型 | 说明 |
|---|---|---|
| symbol | text PK | 统一规范，如 `600519.SH` |
| name | text | 名称 |
| market | text | SH / SZ / BJ |
| type | text | stock / index |
| ipo_date | date | 上市日（Baostock 提供） |
| status | text | listing / delisted |
| data_start / data_end | date | 已入库行情范围，用于按需/增量判断 |
| updated_at | timestamptz | |

### 3.2 `daily_bars`（日线行情，**存后复权 + 不复权 close**）
| 字段 | 类型 | 说明 |
|---|---|---|
| symbol | text | FK |
| date | date | |
| open/high/low/close | numeric | **后复权** |
| volume | numeric | 停牌日为 NULL |
| amount | numeric | |
| raw_close | numeric | **不复权收盘**，用于换算前复权 |
| trade_status | smallint | 1=正常, 0=停牌 |
| | | PK (symbol, date) |

> **为什么这么存**：后复权"钉住起点"，新除权只影响除权日及之后、历史值永不变动（spike 实测重复拉取差 0），所以**增量只往后追加、历史不重算**。前复权"钉住今天"，每次新除权改写整段历史，故不入库、只在展示时换算。`raw_close` 也历史不变，存它是为了算前复权。

### 3.3 其他表（schema 预留，M0 不必实现）
- `users`(id, email unique, password_hash, created_at) — M3
- `watchlist`(user_id, symbol, added_at) — M3
- `compare_groups`(id, user_id, name, symbols, base_date) — M2/M3

> 周/月线**不建表**，查询时由日线聚合。

## 4. symbol 规范（`symbols.py`）

- 内部统一：`{code}.{market}`，market ∈ {SH, SZ, BJ}。指数同形，如 `000300.SH`。
- 转换函数：
  - `to_baostock("600519.SH") -> "sh.600519"`
  - `from_baostock("sh.600519") -> "600519.SH"`
  - `to_akshare("600519.SH") -> "600519"`（纯 code）
- 多市场预留：未来美股 `AAPL.US`、港股 `00700.HK`，由 symbol 后缀路由到对应 provider 与交易日历。

## 5. 核心接口契约

### 5.1 数据类与 DataProvider 抽象（`providers/base.py`）
```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from datetime import date

@dataclass
class Bar:
    date: date
    open: float
    high: float
    low: float
    close: float        # 后复权
    volume: float | None
    amount: float | None
    raw_close: float     # 不复权收盘
    trade_status: int    # 1=正常, 0=停牌

@dataclass
class Instrument:
    symbol: str
    name: str
    market: str
    type: str            # stock / index
    ipo_date: date | None
    status: str

class DataProvider(ABC):
    """所有市场/数据源实现此接口，对上层只暴露标准化结果。symbol 一律用内部规范。"""

    @abstractmethod
    def get_daily_bars(self, symbol: str, start: date, end: date) -> list[Bar]:
        """返回标准化日线:后复权 OHLC + raw_close + trade_status。按 date 升序。"""

    @abstractmethod
    def list_instruments(self) -> list[Instrument]:
        """全市场标的列表(股票 + 指数)。"""

    @abstractmethod
    def get_trade_calendar(self, start: date, end: date) -> list[date]:
        """交易日序列(已排除周末与节假日)。"""
```

### 5.2 BaostockProvider 实现要点（`baostock_provider.py`）
- 生命周期：调用前 `bs.login()`，结束 `bs.logout()`；建议用上下文管理器包住，避免连接泄漏。
- **后复权 + 不复权要两次查询再 merge**：Baostock 一次 `query_history_k_data_plus` 只能取一种复权（`adjustflag` 1/2/3）。取 `adjustflag=1`(后复权)拿 OHLC，取 `adjustflag=3`(不复权)拿 `raw_close`，按 date 对齐合并到 `Bar`。
- `trade_status` 直接映射 Baostock 的 `tradestatus`（1/0）。
- 停牌日：Baostock 占位返回(close 沿用、volume 为空)，保留该行、`volume=None`。
- **已知边界**：超长停牌可能"停返"(缺一段日期而非占位)。M0 不深处理，但 `align` 层要能容忍日期缺口（见 5.5）。
- 代码格式转换走 `symbols.py`。

### 5.3 复权换算（`core/adjust.py`）
```python
def hfq_to_qfq(hfq_closes: list[float], raw_close_latest: float, hfq_close_latest: float) -> list[float]:
    """后复权 → 前复权。
    前复权 = 后复权 × k, 其中 k = raw_close_latest / hfq_close_latest。
    依据:前复权钉住今天真实价,故最新日换算后 == raw_close_latest。
    k 用最新交易日的值(数据须更新到最新)。MVP 可选:单股图先给后复权/不复权,前复权后补。
    """
```

### 5.4 周/月聚合（`core/resample.py`）
```python
def resample(daily: list[Bar], period: str) -> list[Bar]:
    """period ∈ {'W','M'}。按交易日分组:
    open=组内首开, high=组内最高, low=组内最低, close=组内末收, volume=求和。
    停牌日不参与 high/low 失真(可按 trade_status 过滤或沿用)。"""
```

### 5.5 多股对齐（`core/align.py`）
```python
def align(series_by_symbol: dict[str, list[Bar]], trade_days: list[date]) -> dict[str, list[Bar]]:
    """把多只票对齐到统一交易日轴 trade_days。
    - 停牌日(trade_status=0 或缺口): close 用前值横线填充, volume=None。
    - 上市前: 留空(None),不参与对比起点。
    输出每只票等长、与 trade_days 对齐的序列。"""
```

### 5.6 归一化对比（`core/normalize.py`，M2 用，先定契约）
```python
def normalize(aligned: dict[str, list[Bar]], base_date: date) -> dict[str, list[float]]:
    """以 base_date 各标的收盘为基准(=0%),输出累计涨跌幅序列。
    直接用后复权 close 计算——涨跌幅与复权方式无关,故无需换算前复权。
    base_date 当日值=0;之前留空。返回 {symbol: [pct,...]} 与 trade_days 对齐。"""
```

### 5.8 按需加载编排（`services/market_data.py`）
```python
def get_kline(symbol, start, end, period='d', adjust='hfq'):
    """1) 查 coverage;缺失或过期→调 provider.get_daily_bars 抓取→upsert_bars→更新 instruments.coverage
    2) get_bars 取后复权
    3) adjust='qfq' 则用 adjust.hfq_to_qfq 换算; 'none' 用 raw_close
    4) period in {w,m} 则 resample
    5) 返回前端所需 OHLCV 序列"""
```

## 6. M0 最小闭环（验收标准）

1. 首次请求 `GET /api/kline?symbol=600519.SH&period=d` → 自动抓取入库 → 返回后复权日线。
2. 二次请求命中库、不再抓取（按需加载生效）。
3. `period=w/m` 返回正确聚合。
4. `adjust=qfq` 最新日值 == 不复权最新价（验证换算正确）。
5. 停牌日在结果中可识别（trade_status=0，价格横线）。
6. `instruments` 表有该票元数据与 coverage。

跑通这 6 条，M0 完成，骨架可用。

## 7. 给 Claude Code 的实现注意点

- **主源 Baostock**；AKShare 备源走 **sina** 系接口，**避开被限流的 eastmoney**。同一标的固定单源，不跨源拼接。
- 后复权 + 不复权两次查询 merge（5.2）。复权标志显式指定，别用默认。
- `trade_status` 全程透传，是停牌对齐的依据。
- 数值用 `numeric/Decimal`，避免浮点误差污染复权与涨跌幅。
- 盘后更新（M4）挂载点：遍历 `instruments` 已入库标的，按 `coverage` 增量拉新→`upsert_bars`。仅交易日执行（用 5.1 的交易日历）。M0 先不实现，留好函数位。
- 包管理/异步：建议 FastAPI + SQLAlchemy(async) + asyncpg；包管理 uv 或 poetry 自选。
