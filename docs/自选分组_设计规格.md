# 自选股分组管理 — 设计规格

> 在现有自选（watchlist）之上加分组管理。多分组/标签式：一只票可属于多个分组，没归组的显示在"默认分组"。
> 隔离边界沿用 M3：分组与归属**按用户隔离**；行情/标的列表全局共享。

---

## 1. 数据模型（2 张新表）

### `watchlist_groups`（分组，按用户）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | |
| user_id | bigint FK→users.id (ON DELETE CASCADE) | |
| name | text | |
| created_at | timestamptz | |
| | | UNIQUE (user_id, name) 同用户不重名 |

### `watchlist_group_members`（多对多关联）
| 字段 | 类型 | 说明 |
|---|---|---|
| group_id | bigint FK→watchlist_groups.id (ON DELETE CASCADE) | |
| symbol | text | |
| | | PK (group_id, symbol) |

> **默认分组是虚拟的**——不建行。某自选票没有任何 member 记录 = 未分组 = 显示在默认分组。
> - 删分组 → 关联级联删 → 成员若无别的组则回默认分组。
> - 删自选（`DELETE /api/watchlist/{symbol}`）→ 连带清掉该票在本用户各组的关联。
> - 选关联表而非在 watchlist 存数组列：规范化、好查、好级联。

---

## 2. API（均从 JWT 取 user_id，按用户隔离）

分组管理：
- `GET /api/watchlist/groups` → `[{id, name}]`
- `POST /api/watchlist/groups {name}` → 建组；重名 409
- `PATCH /api/watchlist/groups/{id} {name}` → 改名；非本人 404、重名 409
- `DELETE /api/watchlist/groups/{id}` → 204；成员回默认组（级联）

归属：
- `PUT /api/watchlist/{symbol}/groups {group_ids: [...]}` → **替换式**设置该票所属分组集合。
  校验：symbol 在本用户自选内、group_ids 全属本用户；否则 400/404。

读取（改造）：
- `GET /api/watchlist` → 每条新增 `group_ids: [...]`。前端据此分段。

---

## 3. 侧栏 UI（`WatchlistPanel`）

- 顶部 **「＋ 新建分组」**。
- 按分组分段渲染：每个分组一段（组名 + 改名 + 删除）→ 段内是 `group_ids` 含该组的票；最后一段是**默认分组**（`group_ids` 为空的票）。
- 多分组的票**在其所属的每个段各出现一次**（标签式）。
- 每只票行：保留现有（对比勾选 / 名称·价格·涨跌幅红涨绿跌 / × 删除）+ 新增**「分组」菜单**：多选下拉勾选所属分组 → `PUT .../groups`。
- 对比/看图选中状态不变（同一 symbol 多处出现仍是同一选择）。

---

## 4. 不做（YAGNI）
分组排序/拖拽、分组颜色、嵌套分组、对比流程按组筛选。

---

## 5. 验收
1. 建组/改名/删组正常；两个账号分组互不可见（隔离）。
2. 一只票设为属于多个组 → 在多个段都显示；取消某组只去掉该处、自选仍在。
3. 没归组的票显示在默认分组。
4. 删组 → 其成员回默认分组（不丢自选）。
5. 删自选 → 其分组关联一并清掉。
6. 同用户重名分组被拒（409）。
