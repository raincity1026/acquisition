# M1 — 前端看图模块 设计规格

> 用途:给 Claude Code 的实现蓝图。定义组件结构、数据流、klinecharts 配置要点,**不是成品代码**。
> 重要:klinecharts 跨大版本 API 差异大,实现前 `npm i klinecharts@latest` 并对照官方文档核对 `init / applyNewData / createIndicator` 的确切签名。本文给的是使用模式与意图。

---

## 1. M1 目标与范围

用 Vue 3 + klinecharts 把**单股 K 线图**搭起来,对接 M0 的 `/api/kline`。

**M1 做**:单股 K 线蜡烛图 + 五个指标(成交量/MA/MACD/KDJ/RSI)+ 日/周/月切换 + 前/后/不复权切换 + 图表交互(缩放、十字光标)。
**M1 不做**:多股归一化对比(M2)、搜索/自选(M3)、登录(M3)。这些先放最简占位或灰置,但组件边界要为它们留好。

---

## 2. 技术栈

- Vue 3(Composition API)+ Vite + TypeScript
- klinecharts(K 线库,MA/VOL/MACD/KDJ/RSI 全内置,不自研指标)
- 状态:composable 即可(MVP 不必上 Pinia)
- HTTP:axios 或封装的 fetch

---

## 3. 目录结构

```
frontend/
  src/
    api/
      kline.ts          # 封装 /api/kline 请求
    components/
      ChartView.vue     # K 线图组件(封装 klinecharts 实例)
      ChartToolbar.vue  # 控制条:周期 / 复权 / 指标开关
    composables/
      useKline.ts       # 数据获取 + loading/error 状态
    types/
      kline.ts          # 类型定义(Bar 等)
    views/
      MarketView.vue    # 主页面:组合 toolbar + chart
    App.vue
    main.ts
```

---

## 4. 数据流

```
MarketView
  → useKline(symbol, period, adjust)
    → api/kline  →  GET /api/kline?symbol=&period=&adjust=&start=&end=
  → 拿到 JSON → 映射成 klinecharts 格式
  → ChartView.applyData(bars)
```

参数变化(切周期/复权)→ 重新请求 → 重新 applyData。前端**不自己算复权和聚合**,都走后端(M0 已实现)。

---

## 5. 数据格式映射(关键,容易出错)

后端 `/api/kline` 返回每根:
```
{ date: "2024-12-31", open, high, low, close, volume, amount, trade_status }
```

klinecharts 需要(以当前版本字段为准核对):
```
{ timestamp: <毫秒>, open, high, low, close, volume, turnover }
```

映射规则:
- `timestamp = new Date(date).getTime()` ——**date 字符串要转毫秒时间戳**,这步最容易漏。
- `open/high/low/close/volume` 直接对应。
- `amount` → `turnover`(klinecharts 的成交额字段)。
- `trade_status`:停牌日(=0)后端返回 volume 为 null、close 沿用;M1 先保证**不报错**,精细的横线显示留到 M2 对齐再处理。

---

## 6. klinecharts 配置要点

> 使用模式(精确 API 以当前版本文档为准):

- 初始化:`const chart = init(容器元素/id)`,组件卸载时 `dispose()`。
- 灌数据:`chart.applyNewData(bars)`(切周期/复权后重新灌)。
- 主图:默认蜡烛图。
- **指标分配(重要)**:
  - `MA`(均线)——**叠加在主图**(K 线那个 pane 上),默认周期 5/10/20/60。
  - `VOL`(成交量)——独立副图。
  - `MACD`——独立副图。
  - `KDJ`——独立副图。
  - `RSI`——独立副图。
  - 模式类似 `createIndicator('MA', true, { id: 主图paneId })` 叠主图;`createIndicator('VOL')` 建副图。叠加与否、pane 归属按文档参数来。
- 指标开关:用户勾选 → `createIndicator` / `removeIndicator` 动态增删,不要重建整个图。
- **交互全部内置**:缩放、平移、十字光标 tooltip 是 klinecharts 自带的,不用自己写。

---

## 7. 交互与默认值

- **周期切换**(日/周/月):改 `period` 重新请求。周/月是后端聚合返回的。
- **复权切换**(前/后/不复权):改 `adjust` 重新请求。
- **指标开关**:动态增删指标。
- **默认值**:
  - 周期 = 日
  - 复权 = **前复权(qfq)** —— 最贴近真实盘面,符合券商软件习惯
  - 指标 = 默认开 **VOL + MA**,MACD/KDJ/RSI 默认关、按需开

---

## 8. 状态与边界

- **loading**:请求中显示加载态(后端首次抓取某票可能要 2-5 秒)。
- **error**:请求失败友好提示。虽然 M0 已改成"查库优先",但**首次抓取**仍可能撞上 baostock 抖动失败,前端要能优雅显示而不是白屏。
- **空数据**:symbol 查无数据时给提示。
- **停牌日**:不报错即可,精细显示留 M2。

## 9. 为 M2(对比)留的扩展点

不实现,但边界留好:

- `ChartView` 的数据接口设计成"能接收多个 series"的形状(M1 只传一个)。
- 对比态是**归一化折线图**(不是蜡烛图),走 M2 的 `/api/compare`。可在 ChartView 内按"单股/对比"模式切换渲染,或拆出独立的 `CompareChart`——M1 先不写,但 toolbar 留个灰置的"添加对比标的"入口。
- 复用前面线框定的交互:对比态会隐藏指标、用百分比轴、带基准日竖线——那些是 M2 的事。

## 10. M1 验收标准

1. 输入 `600519.SH`,显示完整 K 线蜡烛图。
2. 日/周/月切换正常,周/月是聚合后的。
3. 前/后/不复权切换,K 线量级随之变(后复权上万、前复权/不复权一千多)。
4. 五个指标能开关:MA 叠主图,VOL/MACD/KDJ/RSI 各自副图。
5. 缩放、十字光标 tooltip 正常(klinecharts 自带)。
6. 请求失败有友好提示,不白屏。

跑通这 6 条,M1 完成。

---

## 11. 给 Claude Code 的注意点

- klinecharts 版本 API 差异大,**先装最新版、对照官方文档**核对 `init/applyNewData/createIndicator` 签名再写。
- `date → timestamp` 毫秒转换别漏(klinecharts 用毫秒时间戳)。
- 复权和周月聚合**都走后端**,前端不自己算。
- 默认前复权(qfq)、默认开 VOL+MA。
- **先把单股跑通,别提前做对比**(那是 M2)。
