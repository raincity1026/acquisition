# 股票复盘工具 MVP — 产品需求文档（PRD）

| 项 | 内容 |
|---|---|
| 文档版本 | v0.1（MVP 范围定义） |
| 状态 | 待评审 |
| 产品定位 | 盘后股票复盘工具（Web，多用户） |
| 一句话描述 | 方便地查看个股 K 线，并把多只股票归一化叠加到一张图上对比走势 |

---

## 1. 项目背景与目标

### 1.1 背景
市面上的"复盘工具"大多是短线/游资导向（涨停板、龙虎榜、连板天梯），解决的是"今天哪些票强"；而能干净地做"多标的归一化叠加对比"的，主要是 TradingView 这类海外产品，对 A 股的本土化、数据口径自控和复盘工作流支持有限。本项目要做的是一个**以走势对比为核心、A 股本土化、数据口径自己可控**的盘后复盘工具。

### 1.2 目标
- **产品目标**：让用户能快速查看个股 K 线，并将多只股票放在同一张图中归一化对比走势。
- **项目目标**：作为练手与了解行情类产品框架的载体，同时解决自己日常复盘的实际需求。

### 1.3 非目标（MVP 明确不做）
- 不做实时盯盘 / 分时实时刷新
- 不做交易、下单、模拟交易
- 不做选股、荐股、投资建议
- 不做基本面/财务报表分析

---

## 2. 目标用户与使用场景

### 2.1 目标用户
个人投资者 / 复盘爱好者。MVP 面向**自己 + 朋友**的小范围多用户，不是面向公开市场的商业产品。

### 2.2 核心使用场景
1. 盘后打开，搜索一只股票，查看它近 1–2 年的日/周/月 K 线和技术指标。
2. 把自己关注的几只股票加入自选。
3. 选若干只自选股，叠加到一张图上，以某个基准日为起点，对比谁的累计涨幅更强。

## 4. 功能详述

### 4.1 账号与用户体系（P0）
- 支持注册、登录、登出。MVP 建议邮箱+密码 或 第三方 OAuth（具体见开放问题）。
- 用户数据隔离：**自选股、对比组合属于各自用户**；**行情 K 线数据全局共享**（任一用户按需加载进库的股票，所有人都能直接用——用的人越多，数据库越全）。
- MVP 不做复杂权限/角色，所有注册用户权限相同。

### 4.2 股票搜索（P0）
- 输入代码或名称（支持拼音首字母更好，可选）实时联想。
- 数据来源：预先加载一份**全市场 A 股标的列表**（代码+名称，体量很小），独立于行情数据。
- 搜到的标的若未入库，则在用户首次查看/加自选时按需触发行情抓取。

### 4.3 自选股 / 股票池管理（P0）
- 添加、删除、查看自选列表。
- 列表项展示：代码、名称、最新收盘价、当日涨跌幅（基于已入库数据）。
- 自选股是多股对比的主要来源（从自选里勾选进对比）。

### 4.4 单股 K 线查看（P0）
- 展示某只股票的 K 线图，支持**日 / 周 / 月**切换（周、月由日线聚合生成，不单独存储）。
- 支持时间区间选择（默认近 1–2 年）。
- 默认以**前复权**展示（最新价贴近真实盘面，最直观）。
- 叠加成交量及所选技术指标。

### 4.5 多股归一化叠加对比（P0，核心）
- 从自选/搜索中选择多只股票，叠加到同一张图。
- **默认归一化模式**：选定一个基准日，将各标的该日价格设为 100（或 0%），之后按**累计涨跌幅**绘制。这是本工具的核心，解决不同价位标的无法直接同图对比的问题。
- 基准日：默认取对比区间的起点，**用户可调整**。
- 时间轴按**交易日序列**对齐；不同标的停牌/未上市的缺失日按统一规则处理（见 §6）。
- 建议提供对数坐标可选项（看长期涨幅更合理）。

### 4.6 技术指标（P0）
MVP 支持：成交量、均线 MA、MACD、KDJ/RSI。均线默认周期建议 5/10/20/60（见开放问题）。指标由图表库内置能力实现，不自研算法。

### 4.7 数据保鲜 — 盘后自动更新（P0）
- 后台定时任务（盘后，例如每个交易日 18:00 之后）自动更新**所有已入库股票**的最新行情。
- 仅在 A 股交易日执行（依赖交易日历）。
- 失败重试与数据源降级（主源失败切备源）。

## 5. 数据方案

| 维度 | 决策 |
|---|---|
| 市场 | A 股（一期），架构预留多市场 |
| 数据源 | Baostock 为主（免费、历史日线准、支持复权），AKShare 为补（覆盖广、供标的列表/兜底） |
| 加载策略 | 按需加载——加自选或搜到才抓该股 |
| 历史深度 | 近 1–2 年 |
| 复权 | **入库存后复权**（历史值稳定、只增不改，利于增量更新）；**展示按需换算为前复权** |
| 周期 | 日线为基准存储，周/月线由日线实时聚合 |
| 交易日历 | 维护 A 股交易日历，用于对齐、聚合与定时任务触发 |
| 标的列表 | 预加载全市场代码+名称，支撑搜索，独立于行情数据 |

> 复权说明：后复权"钉住上市起点"，历史值永不变动，新数据只往后追加，最适合天天增量更新的场景；前复权"钉住今天"，每次新除权会改写整段历史，故只在展示层临时换算。

## 6. 关键技术难点与对策

| 难点 | 风险 | 对策 |
|---|---|---|
| 复权 | 用错会出现"假跳空"，污染走势与对比 | 入库后复权，展示前复权；同一标的固定单一数据源，避免跨源复权值对不齐 |
| 停牌 / 未上市对齐 | 多股对比时间轴错位 | 以交易日序列为主轴，缺失日按统一规则（如停牌横线填充 / 上市前留空）处理 |
| 量纲差异 | 高价股与低价股无法同图比较 | 归一化为默认对比模式（累计涨跌幅），而非绝对价 |
| 数据源稳定性 | AKShare 爬取型，受上游改版影响 | 主备降级机制；Baostock 兜底历史数据 |
| 多市场扩展 | 后期加美股/港股伤筋动骨 | 现在就抽象好三层（见 §7） |

## 7. 技术架构

### 7.1 总体分层
```
展示层    Web 前端（K 线图 + 对比 + 自选/搜索）
  ↓ HTTP
服务层    后端 API（鉴权、查询、对比计算）
  ↓
处理层    复权换算、周月聚合、交易日历对齐、归一化、指标
  ↓
存储层    用户数据 + 行情数据
  ↑
接入层    DataProvider（Baostock / AKShare），定时更新
```

### 7.2 建议技术栈
- **前端**：React（或 Vue）+ klinecharts 或 TradingView Lightweight Charts（均内置 K 线与常用指标，支持多 series 叠加）。
- **后端**：Python + FastAPI（A 股数据源生态都在 Python；FastAPI 轻量、异步友好）。
- **存储**：PostgreSQL。单机自用本可用 DuckDB/Parquet，但既然要**多用户上云**，用 PostgreSQL 统一存账号、自选股、行情更省心；数据量不大（按需加载 + 近 1–2 年），单库完全扛得住，未来量大再拆列存。
- **定时任务**：APScheduler / 云定时触发，盘后跑更新。
- **鉴权**：JWT；密码哈希存储（绝不明文）。
- **部署**：上云容器化即可。**MVP 不必上 EKS 全家桶**，先用最简单的单服务 + 托管数据库，避免过度工程化。

### 7.3 多市场扩展的三层预留（一期只实现 A 股）
1. **统一数据源接口** `DataProvider`：定义 `get_kline(symbol, period, start, end, adjust)` 等，各市场各实现一个，对上层只返回标准化 OHLCV。
2. **统一标的标识**：带市场后缀，如 `600519.SH` / `AAPL.US` / `00700.HK`，内部据此路由到对应 provider 与交易日历。
3. **交易日历与时区按市场隔离**：每个市场一套。归一化对比比的是百分比，天然回避跨市场货币问题——这也是把归一化设为默认的又一理由。

## 8. 明确不做的（MVP 范围边界）
- 美股、港股（架构预留，不实现）
- 分钟线 / 实时行情
- 数据导出
- 复杂权限与团队协作
- 自研指标算法（用图表库内置）

---

## 9. 开发里程碑建议

| 阶段 | 目标 | 产出 |
|---|---|---|
| M0 框架 | 搭骨架 + 跑通一条数据链 | DataProvider(Baostock) + 入库 + 一个 API 返回单股 K 线 |
| M1 看图 | 单股 K 线 + 指标 | 前端图表、日/周/月切换、四类指标 |
| M2 对比 | 多股归一化叠加 | 对比计算、基准日可调、交易日对齐 |
| M3 用户 | 账号 + 自选 + 搜索 | 注册登录、自选 CRUD、搜索联想 |
| M4 保鲜 | 盘后自动更新 + 上云 | 定时任务、部署、多设备访问 |

> 练手建议：从 M0 的接入层与处理层切入（复权、对齐、归一化），那是行情类产品真正的 know-how 所在；画图反而是图表库帮你做掉的部分。

## 10. 开放问题（待你拍板的默认值）

以下是访谈未覆盖、我先设了默认值的细节，请确认或调整：

1. **认证方式**：邮箱+密码，还是接第三方 OAuth（微信/Google）？（默认：邮箱+密码，最简单）
2. **一张对比图的标的上限**：建议 ≤ 8 只（再多视觉混乱、性能下降）。
3. **均线默认周期**：建议 MA5 / 10 / 20 / 60，可配置。
4. **自选股是否分组**：MVP 建议单列表；分组放后续。
5. **停牌缺失日处理**：建议默认横线填充（视觉连续），可切换为留空。
6. **复盘标注功能**（在图上画线/写笔记）：MVP 建议不做，先观察需求。
7. **指数支持**：是否把大盘指数（如沪深300）也纳入搜索/对比（常用作对比基准）？建议纳入。
